# 蓝图节点排列方式

Agent 生成或修改蓝图图表时的节点摆放约定，与连接方式无关：用 EngineWire MCP 的批量写图表、UE Python 还是 T3D 文本都适用。这是排版约定，不规定蓝图的逻辑内容。

目标是写完就规整，不需要事后整理。事后整理要先读出整张图的节点和引脚连线，再批量改坐标，消耗远高于创建时顺手带坐标。

## 规则

1. **创建时就带坐标**：每个节点都显式给出位置（MCP 的 `posX` / `posY`，T3D 的 `NodePosX` / `NodePosY`），不依赖自动摆放。
2. **按逻辑分段，一段一行**：例如“开始运行 / 每帧推进 / 分支处理 / 计算位置朝向”各占一行，行间留 400～600 的垂直间距。
3. **执行链从左到右排在同一高度**：同一行的执行节点 Y 相同，列间距约 350～400。
4. **纯函数节点放在使用者下方**：取值与运算放在它们连到的执行节点下方 150～250 处，按数据流从左到右排列。
5. **变量就近取值**：同一个变量在多处使用时，每处各放一个 Get 节点，不要一个 Get 拉长线给远处多个节点共用。
6. **长距离执行线用转接点**：跨段的执行线用 Reroute 节点走直角。
7. **不为排版额外验证**：不为了看排版去截图或重读整张图。与已有节点重叠时工具可能自动挪开节点，剩下的微调交给用户在编辑器里完成（选中节点按 Q 拉直连线，或用 Blueprint Assist 一类插件自动排版）。

## 参考坐标

一张“每帧沿样条线移动”事件图的布局（单位为图表坐标）：

| 段落 | Y | 执行链 X |
|---|---|---|
| 开始运行 | -600 | 0 → 420 → 860 |
| 每帧推进 | 0 | 0 → 500 → 900 → 1520 |
| 到终点换线或销毁 | 450 | 1620 → 2000 → 2400 → 2800 → 3200 → 3560 |
| 计算位置与朝向 | 1300～2150 | 取值与运算从 1700 到 3600，最后的设置节点在 3980 |

## 验证范围

macOS Apple Silicon UE 5.4.4 上用 EngineWire MCP 实际执行过：批量创建带坐标的节点、修改节点坐标、创建转接点并连线，编译通过。目前的 MCP 能力不包含“拉直连线”或自动排版，精确对齐仍由编辑器完成。
