# 蓝图节点排列方式

Agent 生成或修改蓝图图表时的节点摆放约定，与连接方式无关：用 EngineWire MCP 的批量写图表、UE Python 还是 T3D 文本都适用。这是排版约定，不规定蓝图的逻辑内容。

目标是图表在任何时候都规整易读：写完就规整，不需要事后整理。事后整理要先读出整张图的节点和引脚连线，再批量改坐标，消耗远高于创建时顺手带坐标。

## 规则

1. **创建时就带坐标**：每个节点都显式给出位置（MCP 的 `posX` / `posY`，T3D 的 `NodePosX` / `NodePosY`），不依赖自动摆放。坐标优先取 16 的倍数（编辑器网格），为对齐引脚可以微调。
2. **正常长度优先单行，确实超长才折行**：先把相邻逻辑排紧凑；不要为了分段而把正常长度的逻辑强制折行。横向过长、需要过度缩小才能阅读时，才按完整逻辑阶段换到下一行。行距按本行数据区高度加留白决定，示例约 400～640，不作为硬编码阈值。
3. **每行的白色执行引脚保持水平**：从左向右对齐执行引脚中心，不是令 NodePosY 一致。不同形态的执行引脚相对节点顶部高度不同，必须补偿。此次 UE 5.4.4 的 Branch / Entry / Return 与 Set 混排，Set 的 NodePosY 比同排前者多 16 才水平；这是本次节点形态的实测，其他节点单独核对。执行节点列距约 350～400，并按实际宽度调整；每行执行区下方留给数据计算。
4. **数据计算放在执行线下方，分道汇总**：取值与运算放在执行线下方，按子条件拆成几条横向的“车道”，从左到右逐级汇总，最后接到使用它的执行节点（例如分支的 Condition）。
   - 同一级的节点对齐成一列，列距约 300。
   - 汇合节点（AND / OR / 运算）放在它两个输入的中间高度。
   - 返回值的计算放在对应返回节点的正下方。
5. **输入组居中、上下均布，变量就近取值**：左侧输入节点排成一列；两个输入的输出引脚中点，对准右侧使用者的输入区域中心；三个输入时中间输出对齐第 2 输入，上下等距分布。默认节点间距可从 64～80 试起。Get 与使用者的 NodePosX 差约 176～192 是本次短名称样例的起点，实际应按 Get 宽度加短连线留白计算，不能统一使用 320，也不能把坐标差当作线长。单输入可水平对齐；多输入不要求每根数据线都水平。下方偏移统计用于认识节点形态，不覆盖整组居中的排版意图。
6. **跨行和长距离执行线用转接点**：用 Reroute 沿该段外侧留白折返到下一行左端，水平段对齐转接点引脚，尽量避开数据区。多条失败路径可先汇合，再水平接入返回节点；保持逻辑和分支语义不变，不把转接点铺满短线。
7. **保留用户布局**：修改已有图表时不整体重排，新节点按同一套规则插进现有结构；需要腾位置时只挪受影响的那一段。
8. **创建时排好，按异常局部核对**：创建节点就带坐标，不为每次排版反复全图读取或截图。工具碰撞保护若自动挪位，按该节点及相邻节点局部读回，补正最终位置；不能把创建参数或相同 NodePosY 当作执行引脚已经水平的证据。用户要求视觉验收、节点形态首次校准或已发现倾斜时，再做必要的界面检查。

## 参考坐标

### 函数：条件判断后返回

用户手动排版的函数：校验序号在数组范围内且对应点位未被占用，成立返回该点位，否则返回备用点位。

| 区域 | 节点与坐标 |
|---|---|
| 执行线 | 函数入口 (0, 0) → 分支 (2192, 0) → 返回 (2560, 0)；else 返回 (2560, 147) |
| 车道一：序号在范围内 | 取数组 (650, 461) → 长度 (858, 442)；序号 >= 0 (1210, 328)、序号 < 长度 (1216, 432) → AND (1498, 386) |
| 车道二：点位未被占用 | 限制 (544, 656) → 取数组元素 (880, 588) → 包含 (1200, 653) → NOT (1520, 667) |
| 汇总 | AND (1840, 492) → 分支 Condition |
| 返回值 | then：取数组元素 (2256, 192)，在返回节点正下方；else：取数组元素 (2160, 695) |

## 验证范围

macOS Apple Silicon UE 5.4.4 上用 EngineWire MCP 实际执行过：批量创建带坐标的节点、修改节点坐标、创建转接点并连线，编译通过。函数样例的坐标于 Windows UE 5.4.4 用 EngineWire MCP 从用户手排的蓝图读回。目前的 MCP 能力不包含“拉直连线”或自动排版，精确对齐仍由编辑器完成。

### 采样口径

Windows UE 5.4.4，EngineWire MCP `inspect_graph`，每个函数图均启用 `includePins=true`，按 `offset/limit` 读到 `hasMore=false`。用户手排参考蓝图共有 27 个函数图（含构造脚本）、1,046 个节点，逐图数量与函数清单一致。事件图不在本次函数样本内；没有修改参考蓝图。

源节点限定为 `K2Node_VariableGet`，逐条统计其输出直接连接使用者的边，共 317 条；同一 Get 多处使用时每条边各计一次，不穿越 Reroute，也不把数组 Get 的输出混成变量 Get。下表“数组 Get”指使用者为 `K2Node_GetArrayItem`。

定义 **ΔY = Get.NodePosY − 使用者.NodePosY**，正值表示 Get 在下方；单位是图坐标，**不是引脚屏幕坐标或像素**。按返回的 pins 顺序编号数据输入，排除 exec、未接线 self、WorldContextObject / __WorldContext、pinType=None；已接线 Target 保留。该接口未返回全部可见性及引脚几何信息，拆分结构体、隐藏参数和高级引脚需单独核对，不能把此编号直接等同于所有节点的视觉行号。

### 可复用锚点与边界

- **紧凑运算第 1 输入：约 −1**。PromotableOperator 中 −1 有 24/44 条，另有 −2（4 条）、0（2 条）；紧凑函数运算中 −1/0 共 19/25 条。不能套用 +16～20。
- **紧凑运算第 2 输入须看前一行状态**：前一输入已连线的整数减法/布尔或整数比较，+29 有 4 条；前一浮点输入保留默认值框的减法，+35 有 2 条、+34 有 1 条。两组都来自手排样本，不能仅按 int/float 类型决定行距。第 3 输入没有对应变量 Get 直连样本，不外推固定值。
- **数组 Get 的 Array 输入：+5** 有 20/40 条。Index 只有 1 条、偏移 +65，且 Get 与使用者 X 差 1,936，不能据此认定水平对齐应为 +65。第 3 输入不存在。
- **Length：+18～20** 覆盖 21/22 条（+19：13，+18：7，+20：1）；另 1 条为 +112 的远程布线。它与数组 Get 的 +5 不是同一形态。
- **带标题普通纯函数**：第 1 输入 +23 有 2 条；MakeVector 的 Z 是第 3 输入，X/Y 均保留默认值，观测到 +95（1 条）。“+23 起、默认值行每行约 +36”仅为本次测试候选；第 2 输入 +59 尚无同形态的直接证据。带 Target、副标题、执行线或拆分结构体的节点不能套用这个起点。
- **Select、宏、执行节点、返回与 Set** 的样本主要体现分道汇总或放在执行线下方的布局意图，分布宽且未形成统一水平对齐偏移；保留现有手排，不用其众数自动拉直连线。

节点标题不等同于节点形态：同为 CallFunction 也可能渲染成紧凑运算；需结合 nodeName、具体函数与引脚状态分类。上表的宽范围是布局事实，不能把“最常见坐标差”直接升级成所有节点的精确几何规则。

### 最终验收与复用方式

2026-11-03，用户在独立测试蓝图中确认以下排版：短连线、两个输入整组居中、三个输入中间对齐且上下均布、执行引脚真正水平；仅超长逻辑按段折行，并用转接点沿外侧连接。

先前用于采样对比的 +59、数组 Index +35 等候选只属于单输入水平对齐试验，未被确认为多输入组的通用排法；最终多输入布局以输入组中心和均匀间距为准。

最终另建两张纯排版演示函数，未接入游戏事件：正常长度为 4 个连续处理节点，单行，共 19 个节点；超长版本为 18 个连续处理节点，按 3 行、每行 6 个处理节点折行，共 88 个节点（含转接点）。它们仅用于观察排版，不是业务逻辑范例；6 个一行不是所有图的硬限制。

两张图均完成节点坐标读回、执行路径可达性核对、编译和目标资产保存，用户已视觉验收。其他 UE 版本、长变量名、带副标题或不同引脚状态的节点需重新核对尺寸，不外推固定几何。

通用计算：输入节点输出引脚 Y = 使用者输入区域中心 Y + (i − (n−1)/2) × 间距，i 从 0 开始；再减去该输入节点输出引脚相对顶部的偏移，得到 NodePosY。执行节点 NodePosY = 本行执行基准 Y − 本节点执行引脚相对顶部的偏移。
